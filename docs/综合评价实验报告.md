# KeHeng v0.8 综合评价实验报告

## 1. 实验目的

本实验验证“技术能力 + 产业价值”双维度评价是否能够区分不同类型的科技企业，并检查综合报告中的指标、分数和证据链是否稳定传递。实验只调用现有 Technology Agent、Industry Agent、Technology/Industry Evaluation Engine 和 Comprehensive Report Generator，不引入 Finance Agent、外部金融数据或新的模型。

## 2. 实验设计

### 2.1 流程

```text
company_profile.pdf
    ↓
RAG 文档解析与任务隔离
    ↓
Technology Agent ──→ Technology Evaluation
    ↓                         ↓
Industry Agent ───────→ Industry Evaluation
                              ↓
                 60% 技术 + 40% 产业
                              ↓
                   Comprehensive Report
```

默认综合权重来自 `evaluation/composite_weights.yaml`，脚本使用 `rule` 模式运行，保证实验可重复。

### 2.2 案例构成

| 案例 | 设计特征 | 验证问题 |
| --- | --- | --- |
| `case_tech_industry_high` | 技术强、产业强 | 双维度均强时是否得到最高综合分 |
| `case_tech_high_industry_low` | 技术强、产业弱 | 市场、竞争和政策风险能否拉低综合评价 |
| `case_tech_low_industry_high` | 技术弱、产业强 | 行业热门是否会掩盖技术成熟度和自主性不足 |

三组资料均为本地合成材料，PDF 保留页码和原文片段；金标准文件分别记录技术指标、产业指标和综合分预期。

## 3. 评测指标

- 技术评分、产业评分和综合评分是否与金标准一致（容差 0.01）；
- 技术四项、产业四项指标的匹配率；
- 已评分指标是否有有效 E 编号，且 E 编号能在本案例知识库中找到；
- 综合报告是否生成且包含综合分和引用；
- 调整技术/产业权重后，案例排序是否符合权重偏好。

## 4. 实验结果

运行命令：

```powershell
$env:PYTHONPATH = "backend"
backend\.venv\Scripts\python.exe evaluation\evaluate_composite.py `
  --runtime-root runtime\evaluation\composite `
  --output runtime\evaluation\composite_results.json
```

### 4.1 分数与指标结果

| 案例 | 技术分 | 产业分 | 综合分 | 技术指标匹配 | 产业指标匹配 | 证据完整率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 技术强 + 产业强 | 82.75 | 73.75 | 79.15 | 4/4 | 4/4 | 8/8 |
| 技术强 + 产业弱 | 78.25 | 24.50 | 56.75 | 4/4 | 4/4 | 8/8 |
| 技术弱 + 产业强 | 39.38 | 73.75 | 53.13 | 4/4 | 4/4 | 7/7 |

第三个案例的技术知识产权指标为“未评分”，因此证据完整率分母只统计 7 个已评分指标；缺失信息没有被当作零分或虚构证据。

三组案例均生成报告，报告生成率为 **100%（3/3）**，金标准分数全部通过，综合评测通过率为 **100%（3/3）**。

### 4.2 敏感性分析

对已经计算出的技术分和产业分重新组合，不改变任何指标或领域评分：

| 技术权重 | 产业权重 | 排序（从高到低） | 观察 |
| ---: | ---: | --- | --- |
| 0.8 | 0.2 | 技术强产业强 > 技术强产业弱 > 技术弱产业强 | 技术权重偏高，技术强案例占优 |
| 0.6 | 0.4 | 技术强产业强 > 技术强产业弱 > 技术弱产业强 | 默认配置 |
| 0.4 | 0.6 | 技术强产业强 > 技术弱产业强 > 技术强产业弱 | 产业权重提高后排序发生变化 |
| 0.2 | 0.8 | 技术强产业强 > 技术弱产业强 > 技术强产业弱 | 产业权重进一步提高，产业强案例优势扩大 |

排序在技术权重从 0.6 降至 0.4 时发生切换，说明综合模型能够表达投资偏好变化，而不是固定输出单一排序。

## 5. 结果分析

1. 双维度建模有效区分了三类企业：技术强产业弱的企业不会因为技术分较高而获得与双强企业相同的综合评价；产业热门但技术证据不足的企业也不会被行业分完全掩盖。
2. 证据链贯穿两个 Agent 和综合报告。每个已评分指标均有 E 编号，报告引用仍保留文档名、页码和原文片段。
3. 缺失知识产权材料的案例保持未评分，综合引擎按有效指标权重归一化，符合“缺失不等于零分”的设计原则。
4. 敏感性分析为论文和答辩提供了可解释实验：权重变化会影响技术强/产业弱与技术弱/产业强两类企业的相对排序。

## 6. 局限与解释边界

- 当前案例为合成文本，不能代表真实行业统计或融资结果；
- Industry Agent 仍为规则型信息抽取，尚未评估真实 LLM 模式下的稳定性；
- 固定权重用于展示方法链路，不构成真实信贷或投资建议；
- 产业指标反映材料中的企业事实和行业描述，不等同于独立市场调查。

## 7. 结论与下一步

v0.8 已建立可回归运行的综合评价样例集、金标准、指标/证据质量统计和权重敏感性分析。当前建议保持 Technology 与 Industry 评价边界、配置化权重和证据约束，下一阶段优先补充更多真实脱敏材料和人工标注一致性评估，再考虑 LLM 抽取对比；暂不引入 Finance Agent 或复杂外部数据平台。
