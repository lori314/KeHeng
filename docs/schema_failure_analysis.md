# v1.1 Schema Failure 分析

## 数据范围

本分析读取 `runtime/experiments/v10/error_cases.json`。该文件记录 30 次 LLM 工作流运行中的 8 次 `schema_failure`（占全部运行 26.67%，占失败记录 100%），但 v1.0 没有持久化模型原始响应正文，因此只能对已记录的错误进行可靠分类；不能把缺少的原文推断成某一种具体格式错误。

| 分类 | 数量 | 占失败比例 | v1.0 可核验示例 | 是否可通过格式修复解决 |
|---|---:|---:|---|---|
| 缺少字段 | 0（未记录） | 0% | 未持久化字段级校验信息 | 待 v1.1 原始响应确认 |
| 字段类型错误 | 0（未记录） | 0% | 未持久化字段级校验信息 | 待确认；通常可修复 |
| JSON 被 Markdown 包裹 | 0（未记录） | 0% | 未持久化原文 | 通常可以 |
| JSON 前后存在解释文字 | 0（未记录） | 0% | 未持久化原文 | 通常可以 |
| evidence 格式错误 | 0（未记录） | 0% | 未持久化字段级校验信息 | 仅当属于结构格式错误时可以 |
| score 格式错误 | 0（未记录） | 0% | 未持久化字段级校验信息 | 仅当属于类型/范围格式错误时可以 |
| score 范围错误 | 0（未记录） | 0% | 未持久化字段级校验信息 | 可修复结构，但不能擅自改事实或分数含义 |
| 其他 schema_failure（未细分） | 8 | 100% | `AnalysisServiceError: LLM 抽取失败（schema_failure）` | 需要 v1.1 原始响应定位 |

## 结论

v1.0 的失败全部被上层统一记录为 `schema_failure`，没有出现网络、超时、429 或 5xx。现有证据支持“失败发生在结构化契约阶段”，但不支持进一步声称其中某一比例是 Markdown、缺字段或类型错误。

补充核验：历史 `runtime/experiments/real_llm/raw_runs.json` 保留过同类失败的原文，其中可见 `confidence: "high"/"medium"` 这类字符串与契约要求的 `0--1` 数字不符，属于“字段类型错误”，可通过格式修复解决。该历史样本不能反推 v1.0 八次失败的精确构成，因此 v1.0 表格仍按已持久化证据统计。

v1.1 将在 Provider 观测中记录首轮/修复轮状态、响应长度和字段校验结果，并将原始响应以脱敏实验记录保存，从而把这类“未细分”拆成可审计子类。格式修复只允许一次，只改变 JSON 形状，不重新分析事实，也不触发 rule fallback。

v1.1 复验结果：30 次运行首次结构化成功 30 次，schema_failure 为 0，未触发 repair；因此修复路径已通过契约单元测试，但尚无真实失败样本可估计 repair 成功率。
