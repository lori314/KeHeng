# KeHeng 创新点总结

## 1. 基于证据约束 RAG 的企业技术信息抽取方法

### 技术描述

系统先对企业 PDF 进行解析、切分和任务隔离检索，再将带文档、页码和原文的证据 chunk 输入 Agent。每个结论通过 E 编号绑定到检索证据，报告阶段继续校验证据映射。

### 解决问题

解决企业技术资料分散、人工定位成本高、模型引用来源不可追踪的问题；同时降低跨企业资料混入和无依据生成的风险。

### 与传统方案区别

传统摘要系统通常只输出自然语言总结，无法稳定定位页码和原文。KeHeng 将“检索证据—E 编号—结论—报告引用”作为完整数据链路，证据不是结果生成后的附加说明，而是分析输入和输出契约的一部分。

### 支持与边界

- 代码支持：`backend/app/rag/`、Technology/Industry Agent 的证据模型、Report Generator 的引用校验。
- 实验支持：v1.1 有效证据引用率 100%，未发现无效 E 编号。
- 对比边界：已验证证据链和任务隔离，不等同于证明 RAG 在所有行业资料上的召回率优于其他向量库。

## 2. LLM 信息理解与确定性评价解耦框架

### 技术描述

LLM 负责从非结构化资料中理解事实、提取技术和产业指标并给出理由；Evaluation Engine 从 YAML 指标与权重配置读取指标，执行确定性加权、状态判断和证据映射。LLM 不直接生成 Technology Score 或 Overall Score。

### 解决问题

解决“为什么是这个分数”“模型换了以后分数是否还能复算”的可信度问题，避免模型随机性直接成为融资评价规则。

### 与传统方案区别

区别于端到端 LLM 评分或人工在报告中手工填写分数，KeHeng 将理解层与决策计算层分离。同一抽取结果在同一配置下可重复计算，评分规则也可以独立审计和替换。

### 支持与边界

- 代码支持：`evaluation/` 中的固定指标、权重、确定性评分和综合评分模块；Report Generator 不重新评分。
- 实验支持：Rule 与 LLM 共用 Evaluation Engine，v1.1 记录了两种模式的分数差异和指标 MAE。
- 对比边界：能够说明职责解耦和可复算性，不能据此声称评分已经达到专家或生产级准确率。

## 3. 技术价值与产业价值融合的双维评价模型

### 技术描述

Technology Agent 评价技术自主性、创新能力、知识产权和成熟度；Industry Agent 评价市场潜力、行业成长性、竞争位置和政策环境。两个维度独立抽取、独立评分，再按配置权重进行综合评价。

### 解决问题

解决只看技术强弱无法反映商业化环境，或只看热门行业无法证明企业自身竞争力的问题。双维结果能够表达“技术强但市场弱”“产业热门但技术证据不足”等差异。

### 与传统方案区别

传统单一技术评分或单一行业判断容易把不同事实混在一起。KeHeng 通过 Agent 边界、指标集合和权重配置将企业内部能力与外部产业位置分开建模，并保留各自证据。

### 支持与边界

- 代码支持：Technology/Industry 两个 Agent、独立指标配置和 `composite_scoring.py` 的技术 60%/产业 40%融合。
- 实验支持：综合案例覆盖“技术强/产业弱”和“技术弱/产业强”，真实案例也分别报告技术与产业状态。
- 对比边界：证明模型能够表达双维差异，不证明双维分数等同于真实商业化或融资结果。

## 4. 面向证据不足场景的可信评价状态机制

### 技术描述

Evaluation 输出 `fully_scored`、`partially_scored`、`insufficient_evidence` 和 `pipeline_failed`，并同时返回技术、产业和总体 evidence coverage。缺失一级维度时 Overall Score 为 `null`，不对剩余维度做虚假的完整化处理。

### 解决问题

解决金融尽调中资料不完整却被系统强行打分的问题，同时区分“不能评价”和“系统运行失败”，便于人工补充资料或转人工复核。

### 与传统方案区别

传统 Demo 往往用默认值、零分或模型猜测填满结果。KeHeng 将“不评分”作为正式状态和可展示结果，允许报告明确表达证据边界，这比单纯追求高成功率更符合风险场景。

### 支持与边界

- 代码支持：`ComprehensiveEvaluationResult` 的 `assessment_status` 和 `evidence_coverage` 字段，以及缺失维度不强行生成 Overall 的逻辑。
- 实验支持：六家真实企业中 4 家为 `insufficient_evidence`，宁德时代 v1.1 重跑后仍因证据不足保持空分数。
- 对比边界：验证了系统能表达资料不足，不代表该状态判定已通过金融专家统计验证。
