# 科衡测试计划

## Iteration 05 回归范围

结构化输出修复需覆盖合法修复、未知引用拒绝、字段级错误诊断，以及系统失败与业务证据不足状态分离。上下文组装需覆盖查询组轮转、重叠句去重、完整句预算约束和来源定位保留；Web 回放需在已保存产物存在时显示模型/运行日期并保证不调用模型，缺少本地历史文件时明确提示。本轮不新增真实模型调用验证。

## Iteration 06 发布候选检查

技术摘要契约须区分 `supported` 与 `insufficient_evidence`：事实摘要需显式携带当前任务证据 ID；无证据拒答使用固定文本和空证据列表；缺少证据字段、未知引用或不符合拒答文本的事实摘要不能作为成功结果。密钥发现只允许显式环境变量，不读取个人 CSV。公开离线门禁为合成评价案例、Provider/Agent 契约回归和配置安全测试，并构建前端；干净快照还需实际验证依赖安装、规则演示上传和未配置模型的明确失败。真实模型语义仍需人工复核，格式校验通过不能替代事实/引文支持验证。

## 1. 测试目标

本计划用于验证科衡在功能、数据、AI 效果、安全、性能和可审计性方面满足已评审需求，并为发布提供可复查证据。当前为初始策略；具体工具、环境、阈值和排期将在技术选型与样本基线建立后补充。

## 2. 测试原则

- 测试围绕风险和验收标准，不以覆盖率数字替代有效断言。
- 确定性代码与概率性 AI 能力采用不同但衔接的验证方法。
- 固定样本、模型、提示词、知识库和配置版本，保证结果可比较。
- 正常、异常、边界、降级、权限和恢复场景同等重要。
- 测试数据使用合成、脱敏或获准公开数据，并与生产隔离。
- 高影响结果须包含专家复核，自动评测不作为唯一发布依据。

## 3. 测试范围

计划覆盖任务与资料管理、文档解析、知识索引与检索、专项 Agent、指标评价、报告生成与审阅、身份权限、审计、配置治理、外部组件适配及部署运行。

当前已对公开虚构样例执行 PDF 解析、任务隔离检索、指标提取、确定性评分、报告装配、报告 API、PDF 上传任务接口和统一分析服务的自动化验证。v0.5.5 在 `data/evaluation_cases/` 增加三个完全合成的固定案例，覆盖证据充分、材料不足及否定/未来语义，并由 `evaluation/evaluate_pipeline.py` 统计报告生成成功率、E 编号引用完整率、`task_id` 隔离正确率、关键字段完整率、指标期望匹配率和期望证据命中率。模型效果、性能、安全和真实浏览器自动化验收仍需获授权样本及已评审阈值。

Iteration 03 补充 `tests/test_iteration03_product.py`：验证无密钥规则技术模式、真实模式配置缺失拒绝回退、双模块测试替身成功、单/全部模块失败状态、BM25 task_id 隔离、实际 SMIC 孤儿引用与 Agent 对同类未绑定引用的拒绝。离线检索命令比较 hash baseline、双语查询、BM25 与 RRF；当前八个候选标签均待人工确认，相关指标只作暂定候选统计。真实模型配对测试计划为两企业×两检索配置×两 Agent 主请求共 8 次，格式修复最多另加 8 次；本轮不执行。

## 4. 测试层次

| 层次 | 目标 | 典型对象 |
| --- | --- | --- |
| 静态检查 | 发现格式、类型、安全和配置问题 | 代码、依赖、YAML、接口模式 |
| 单元测试 | 验证确定性逻辑和边界 | 权限判断、状态流转、评分规则、引用解析 |
| 契约测试 | 稳定模块和外部适配接口 | API、事件、Agent/RAG 输入输出模式 |
| 集成测试 | 验证组件协作和数据一致性 | 存储、索引、工作流、模型适配器 |
| 端到端测试 | 验证用户闭环 | 上传到报告审阅和发布 |
| AI 离线评测 | 衡量检索、分析和报告质量 | 固定金标准样本与专家量表 |
| 安全测试 | 验证权限和攻击防护 | 越权、注入、泄露、恶意文件 |
| 性能与可靠性测试 | 验证容量、恢复和降级 | 并发、长任务、重试、故障注入 |
| 用户验收测试 | 确认业务可用性 | 代表性企业案例和审批流程 |

## 5. 重点功能测试

### 5.1 任务与资料

验证任务状态流转、重复上传、损坏/超限/恶意文件、资料版本、授权到期、失败重试和归档。确认任何失败都可见且不会把未处理资料标记为已完成。

### 5.2 解析、索引与检索

针对文本、扫描页、表格、混合版式和低质量文档建立样本。验证页码/位置映射、表格结构、元数据、权限过滤、索引更新与删除。检索测试包含明确答案、跨文档答案、冲突答案、无答案和越权诱导。

### 5.3 Agent 与报告

验证结构化输出、证据最小要求、引用支持度、冲突识别、信息缺口、拒答、超时和部分失败。报告需检查章节完整、数值一致、专项结论无误合并、反证未遗漏、引用可跳转、人工修订可保留。

### 5.4 评价

验证权重和校验约束、边界值、单位/精度、缺失值、异常值、否决风险、配置生效范围和历史结果重放。使用手工可计算的小样本对照；权重调整需进行敏感性回归。

### 5.5 权限和审计

验证组织、任务、角色和资料级授权组合，特别关注检索索引、缓存、导出和后台任务中的越权。关键操作应产生完整、不可由普通用户修改的审计记录。

## 6. AI 评测设计

### 6.1 数据集

评测集按行业、企业阶段、资料类型、资料质量、信息完整度和风险类型分层，划分开发集、回归集与受控验收集。样本需记录来源、授权、版本、标注人和争议项。验收集避免被提示词调优直接污染。

### 6.2 指标方向

| 能力 | 候选指标 |
| --- | --- |
| 解析 | 文本/表格/字段正确性、位置映射正确性、失败识别率 |
| 检索 | Recall@K、排序质量、无答案识别、权限泄漏次数 |
| 专项分析 | 事实一致性、引用支持率、要点覆盖、冲突发现、专家可用性 |
| 报告 | 章节覆盖、前后一致、关键数字一致、引用正确、限制表达 |
| 安全 | 注入成功率、敏感数据泄露、越权工具调用、跨任务污染 |
| 运行 | 成功率、时延分位、重试率、单位任务资源与成本 |

最终指标、阈值和抽样置信区间需由业务、AI、测试和风险人员联合确认。专家评分应使用统一量表并评估标注一致性。

### 6.3 回归策略

模型、提示词、分块、检索、工具、指标或权重变更均触发相关固定集回归。比较总体与分层结果，避免平均分掩盖特定行业或资料类型退化。变化超过约定阈值时阻断发布或完成风险接受。

## 7. 安全测试

测试场景包括文件恶意内容、提示词注入、间接注入、跨任务检索、对象级越权、角色提升、敏感日志、导出绕过、秘密泄露、依赖与镜像漏洞、拒绝服务和审计篡改。安全测试使用无害载荷并在获授权环境进行。

正式接入外部模型或数据服务前，应验证数据字段、传输区域、留存策略、供应商访问和失败降级是否符合审批结论。

## 8. 性能、稳定性与恢复

在样本规模确定后建立小、中、大任务基线，测量上传/解析/索引耗时、查询响应、报告完成时限、并发和资源成本。通过超时、限流、模型不可用、存储短暂失败和工作进程中断验证幂等、重试、断点恢复、熔断和人工接管。容量阈值不在缺乏业务目标时预设。

## 9. 测试环境与数据

开发、测试、验收和生产环境隔离；测试环境使用独立身份、密钥、存储和索引。每次 AI 评测记录代码版本、镜像/依赖、模型和参数、提示词、数据集、知识库、配置及运行时间。测试结果和失败样本的访问权限不得低于源资料。

## 10. 缺陷管理

缺陷按影响分级：导致越权、敏感泄露、关键错误结论或审计失真者为发布阻断；核心流程不可用或大范围错误通常为高优先级；局部可绕过问题按影响安排。缺陷记录应包含环境、输入版本、复现步骤、实际/预期结果、证据和影响范围。修复后增加回归用例。

## 11. 进入与退出条件

进入系统测试前：需求与接口已评审，环境可重建，测试数据获准，核心单元/契约测试通过，版本可识别。

建议发布退出条件：

- 核心业务与权限场景通过，无未接受的阻断缺陷。
- AI 质量达到已批准的总体与分层阈值，关键引用经抽查合格。
- 重要安全问题已修复或由有权责任人书面接受。
- 性能与恢复满足约定目标，监控、回滚和人工降级可用。
- 报告生成条件可追溯，测试报告和剩余风险完成评审。

## Iteration 04 证据锚点评测回归

- 支持句落在不同重叠 chunk ID 时按 PDF 哈希、页码和精确原文统计，不把旧 task-scoped chunk ID 当成跨任务金标准。
- 分别检查检索 top-k 原文命中和真实上下文预算截断后的原文命中；规范化不得丢失数字、否定、标点或单位。
- 未标注/AI 复核候选不得转换成专家 gold；模型探索性运行输出不得进入正式准确率。
- 配对运行检查无密钥预检为零请求，并校验鉴权/余额/额度/连续传输错误停止策略。
