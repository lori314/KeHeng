# 科衡测试计划

## V2 端到端 Review Smoke Runner

`scripts/run_end_to_end_review.py` 在显式配置真实 LLM Provider 与 Tavily 时，顺序调用主体解析/迭代研究、科技语义加工和科技金融推理，并把知识库、`review.json` 与 `review.md` 写入 `runtime/review/end_to_end/<run_id>/` 的独立目录。缺少任一 Provider 配置时只报告 `REAL_SMOKE_NOT_RUN` 和缺失类别，不构造替代输出。Runner 不调用 LLM 对自身结果评分；质量检查由离线确定性函数完成，覆盖引用/证据 ID、snippet-only、来源 host/type 混合、milestone 支持和禁止融资裁决字段。`tests/test_end_to_end_review_runner.py` 只测试这些辅助逻辑及无凭据预检，不访问外部网络。真实 smoke 工件含公开网页材料及模型派生内容，属于运行数据，不提交版本库；单次公开企业运行也不替代专家事实核验或固定样本 AI 评测。

## Iteration 05 回归范围

结构化输出修复需覆盖合法修复、未知引用拒绝、字段级错误诊断，以及系统失败与业务证据不足状态分离。上下文组装需覆盖查询组轮转、重叠句去重、完整句预算约束和来源定位保留；Web 回放需在已保存产物存在时显示模型/运行日期并保证不调用模型，缺少本地历史文件时明确提示。本轮不新增真实模型调用验证。

## Iteration 06 发布候选检查

技术摘要契约须区分 `supported` 与 `insufficient_evidence`：事实摘要需显式携带当前任务证据 ID；无证据拒答使用固定文本和空证据列表；缺少证据字段、未知引用或不符合拒答文本的事实摘要不能作为成功结果。密钥发现只允许显式环境变量，不读取个人 CSV。公开离线门禁为合成评价案例、Provider/Agent 契约回归和配置安全测试，并构建前端；干净快照还需实际验证依赖安装、规则演示上传和未配置模型的明确失败。真实模型语义仍需人工复核，格式校验通过不能替代事实/引文支持验证。

## 1. 测试目标

本计划用于验证科衡在功能、数据、AI 效果、安全、性能和可审计性方面满足已评审需求，并为发布提供可复查证据。当前为初始策略；具体工具、环境、阈值和排期将在技术选型与样本基线建立后补充。

## 2. 测试原则

- 测试围绕风险和验收标准，不以覆盖率数字替代有效断言。
- 确定性代码与概率性 AI 能力采用不同但衔接的验证方法。
- 固定样本、模型、提示词、知识库和配置版本，保证结果可比较。
- 正常、异常、边界、降级、权限和恢复场景同等重要。
- 测试数据使用合成、脱敏或获准公开数据，并与生产隔离。
- 高影响结果须包含专家复核，自动评测不作为唯一发布依据。

## 3. 测试范围

计划覆盖任务与资料管理、文档解析、知识索引与检索、专项 Agent、指标评价、报告生成与审阅、身份权限、审计、配置治理、外部组件适配及部署运行。

当前已对公开虚构样例执行 PDF 解析、任务隔离检索、指标提取、确定性评分、报告装配、报告 API、PDF 上传任务接口和统一分析服务的自动化验证。v0.5.5 在 `data/evaluation_cases/` 增加三个完全合成的固定案例，覆盖证据充分、材料不足及否定/未来语义，并由 `evaluation/evaluate_pipeline.py` 统计报告生成成功率、E 编号引用完整率、`task_id` 隔离正确率、关键字段完整率、指标期望匹配率和期望证据命中率。模型效果、性能、安全和真实浏览器自动化验收仍需获授权样本及已评审阈值。

Iteration 03 补充 `tests/test_iteration03_product.py`：验证无密钥规则技术模式、真实模式配置缺失拒绝回退、双模块测试替身成功、单/全部模块失败状态、BM25 task_id 隔离、实际 SMIC 孤儿引用与 Agent 对同类未绑定引用的拒绝。离线检索命令比较 hash baseline、双语查询、BM25 与 RRF；当前八个候选标签均待人工确认，相关指标只作暂定候选统计。真实模型配对测试计划为两企业×两检索配置×两 Agent 主请求共 8 次，格式修复最多另加 8 次；本轮不执行。

## 5. 重点功能测试

### 5.1 任务与资料

验证任务状态流转、重复上传、损坏/超限/恶意文件、资料版本、授权到期、失败重试和归档。确认任何失败都可见且不会把未处理资料标记为已完成。

### 5.2 解析、索引与检索

针对文本、扫描页、表格、混合版式和低质量文档建立样本。验证页码/位置映射、表格结构、元数据、权限过滤、索引更新与删除。检索测试包含明确答案、跨文档答案、冲突答案、无答案和越权诱导。

### 5.3 Agent 与报告

验证结构化输出、证据最小要求、引用支持度、冲突识别、信息缺口、拒答、超时和部分失败。报告需检查章节完整、数值一致、专项结论无误合并、反证未遗漏、引用可跳转、人工修订可保留。

### 5.4 评价

验证权重和校验约束、边界值、单位/精度、缺失值、异常值、否决风险、配置生效范围和历史结果重放。使用手工可计算的小样本对照；权重调整需进行敏感性回归。

### 5.5 权限和审计

验证组织、任务、角色和资料级授权组合，特别关注检索索引、缓存、导出和后台任务中的越权。关键操作应产生完整、不可由普通用户修改的审计记录。

## 6. AI 评测设计

### 6.1 数据集

评测集按行业、企业阶段、资料类型、资料质量、信息完整度和风险类型分层，划分开发集、回归集与受控验收集。样本需记录来源、授权、版本、标注人和争议项。验收集避免被提示词调优直接污染。

### 6.2 指标方向

| 能力 | 候选指标 |
| --- | --- |
| 解析 | 文本/表格/字段正确性、位置映射正确性、失败识别率 |
| 检索 | Recall@K、排序质量、无答案识别、权限泄漏次数 |
| 专项分析 | 事实一致性、引用支持率、要点覆盖、冲突发现、专家可用性 |
| 报告 | 章节覆盖、前后一致、关键数字一致、引用正确、限制表达 |
| 安全 | 注入成功率、敏感数据泄露、越权工具调用、跨任务污染 |
| 运行 | 成功率、时延分位、重试率、单位任务资源与成本 |

最终指标、阈值和抽样置信区间需由业务、AI、测试和风险人员联合确认。专家评分应使用统一量表并评估标注一致性。

### 6.3 回归策略

模型、提示词、分块、检索、工具、指标或权重变更均触发相关固定集回归。比较总体与分层结果，避免平均分掩盖特定行业或资料类型退化。变化超过约定阈值时阻断发布或完成风险接受。

## 7. 安全测试

测试场景包括文件恶意内容、提示词注入、间接注入、跨任务检索、对象级越权、角色提升、敏感日志、导出绕过、秘密泄露、依赖与镜像漏洞、拒绝服务和审计篡改。安全测试使用无害载荷并在获授权环境进行。

正式接入外部模型或数据服务前，应验证数据字段、传输区域、留存策略、供应商访问和失败降级是否符合审批结论。

## 8. 性能、稳定性与恢复

在样本规模确定后建立小、中、大任务基线，测量上传/解析/索引耗时、查询响应、报告完成时限、并发和资源成本。通过超时、限流、模型不可用、存储短暂失败和工作进程中断验证幂等、重试、断点恢复、熔断和人工接管。容量阈值不在缺乏业务目标时预设。

## 9. 测试环境与数据

开发、测试、验收和生产环境隔离；测试环境使用独立身份、密钥、存储和索引。每次 AI 评测记录代码版本、镜像/依赖、模型和参数、提示词、数据集、知识库、配置及运行时间。测试结果和失败样本的访问权限不得低于源资料。

## 10. 缺陷管理

缺陷按影响分级：导致越权、敏感泄露、关键错误结论或审计失真者为发布阻断；核心流程不可用或大范围错误通常为高优先级；局部可绕过问题按影响安排。缺陷记录应包含环境、输入版本、复现步骤、实际/预期结果、证据和影响范围。修复后增加回归用例。

## 11. 进入与退出条件

进入系统测试前：需求与接口已评审，环境可重建，测试数据获准，核心单元/契约测试通过，版本可识别。

建议发布退出条件：

- 核心业务与权限场景通过，无未接受的阻断缺陷。
- AI 质量达到已批准的总体与分层阈值，关键引用经抽查合格。
- 重要安全问题已修复或由有权责任人书面接受。
- 性能与恢复满足约定目标，监控、回滚和人工降级可用。
- 报告生成条件可追溯，测试报告和剩余风险完成评审。

## Entity Resolver 输入归属与诊断回归

- LLM identity draft 不含 `input_name`；最终结果的输入名称必须来自 resolver 调用参数。
- 寒武纪式官网页面使用合成离线 SearchResult fixture 验证身份字段正文支持和 `www.`/apex host 等价。
- 覆盖 resolved 缺少名称/证据、ambiguous 候选不足、unresolved 携带身份字段、无效证据 URL、格式错误/无证据 USCC、未支持名称/别名/官网等 deterministic validation diagnostics。
- 官网 host 归一化须接受 apex、`www.` 与合法子域，并拒绝相似但非子域 host。
- Draft contract 覆盖 resolved 缺少 canonical name、ambiguous 候选不足、unresolved 携带主张/候选；字段状态不一致在结构化契约校验阶段拒绝。
- 官网来源回归覆盖模型声明证据优先、同 host 页面自证、第三方页面外链不构成自证、多 host 自证冲突留空及安全诊断。
- `source-hosts.v2` 覆盖 cninfo.com.cn、sse.com.cn、szse.cn 的 `exchange_disclosure` 分类，并确认东方财富、雪球、新浪、搜狐等门户不被误判为交易所披露来源；交易所类别映射 `authoritative_public_record`。
- Smoke source inventory 覆盖 source-level 来源类型/质量分布、权威/一方比例、unknown web 比例和 resolved 无官网 warning。
- Diagnostics 不得包含 claim 完整值、完整网页正文或模型原始输出。

## Entity Resolver 证据必填与失败快照

- JSON Schema 的 `EntityResolutionDraft.evidence_urls` 必须为 required 且 `minItems=1`；空列表在 Pydantic contract 校验阶段触发至多一次结构修复。
- 有检索结果时 resolved、ambiguous、unresolved 均须引用至少一个实际输入 URL；无检索结果继续走确定性 unresolved fast path。
- runner 失败报告保留调用方 input_name，并显示查询文本、身份结果数、sources_found 和失败阶段；未完成的 rounds/sources_ingested 不得伪造为完成数据。
- 使用三个离线 SearchResult 的端到端失败 fixture 验证部分执行快照进入 review.json 与 review.md，且快照不含 URL、网页正文或密钥。

## Relevance Gate fail-closed 回归

- 模型仅以批内 page_id 返回分类；可核验 relevance 引文必须经 NFKC/空白规范化后原文命中标题、摘要或正文，URL 由应用按 page_id 映射。
- 覆盖 relevant/irrelevant 的精确引文、改写或缺失引文降为 uncertain、uncertain 无引文、缺失 ID、重复 ID、未知 ID 和结构化调用失败。
- 调用失败时待判结果均为 uncertain；身份证据 URL 与官网 host 快速路径仍可 deterministic relevant，且计数进入每轮 relevance diagnostics。
- uncertain/irrelevant 结果不得写入共享知识库或计入已摄入来源。

## Technology Semantic evidence selector 回归

- 覆盖来源轮转和每来源最多 2 个、现有 SourceQuality 优先级、全文优先、48,000 字符/3,200 字符/chunk 及 18 chunk 硬限制。
- 验证明显转载近重复过滤、独立不同文本保留、同一输入重跑时 chunk 顺序与 selection report 稳定。
- Processor classifier 与 extractor 必须收到同一 selector 选出的证据正文；classifier 使用 E<n> 且不含内部 chunk ID/Citation，extractor 使用稳定 chunk ID；实传正文字符数不超 selector report/预算，原 GENERAL chunk 正文保持不变。
- classifier 超时 fixture 验证 processor trace 保留 `domain_template_classifier` 子阶段与已完成的 selection stats；runner review 将其写入 JSON 和 Markdown。

## Technology Fact Extractor batch 回归

- 18 个输入 chunk 按原始顺序形成 6 次批调用，每批不超过 3 个 chunk，且每个输入 chunk 恰好发送一次。
- 受控并发测试验证最多 2 个请求同时执行；让后批先完成，验证结果仍按 batch index 和批内事实顺序稳定合并。
- 跨 batch 的 selected chunk 引用必须拒绝并记录 `invalid_batch_chunk_reference`；全局 selected 集合校验仍保留。
- 单批 timeout 时确认该批 facts 不接纳、剩余批继续、partial report 显示失败 batch 与受影响 chunk gap；所有批次失败时必须抛出原始 provider category。
- 报告验证覆盖批次数、成功/失败批次、chunk 覆盖数、fact 数、batch size、并发上限、error categories、无效引用和 tag 计数，并由 review Markdown 显示。

## Structured LLM thinking transport 回归

- `KEHENG_LLM_ENABLE_THINKING` 未设置时请求体不含 `enable_thinking`。
- 设置为 true/false 时，请求体顶层分别传递布尔值 `true`/`false`；不放入 user payload，也不改变 timeout。
