# 科衡项目总结

## 1. 文档说明

本文是随项目推进持续更新的阶段总结。当前记录项目初始化成果、约束和下一阶段建议，不表示业务系统已经开发完成。后续每个里程碑结束时应补充实际范围、质量数据、偏差、经验和遗留问题。

## 2. 项目愿景

科衡旨在帮助金融机构更高效、更有依据地理解科技型企业的技术价值、产业潜力、财务经营质量和风险因素。系统拟将多模态资料治理、RAG、专业智能体和多指标决策分析组合成可审计的辅助尽调流程，并以人工复核保障高影响决策的责任边界。

## 3. 当前阶段成果

截至本次初始化，项目完成了以下基础建设：

- 建立前端、后端、Agent、RAG、评价、数据、配置、脚本和测试的目录边界。
- 建立项目说明和适用于全仓库的 AI 辅助开发规范。
- 形成软件开发计划、需求、系统、AI、数据和测试文档初稿。
- 给出指标与权重的可评审草案，并明确其非生产状态。
- 保留评分模块文件位置，但未实现任何业务计算逻辑。

本阶段没有安装依赖，没有生成前后端业务代码，没有接入外部 API，也没有实现 RAG 或 Agent 功能。

## 4. 已形成的关键共识

1. 项目以可靠工程与受控演进为优先，不以快速 Demo 代替可验收系统。
2. 所有重要 AI 结论必须有可定位证据，并区分事实、推断、规则结果和人工意见。
3. 技术、产业、财务、报告、RAG 和评价能力保持模块化，通过数据契约协作。
4. 模型、提示词、知识库、指标、权重和报告均需版本化和可追溯。
5. 缺失或冲突证据应触发降级、待核验或人工复核，不能由模型虚构补齐。
6. 系统是辅助工具，正式融资、授信或投资结论必须经过有权人员复核。

## 5. 当前状态判断

项目处于 M0“启动与规范建设”阶段，已经具备开展跨角色评审的文档基线，但尚不具备运行、演示或业务试点条件。当前技术路线仍保持供应商和框架中立；性能、AI 效果、报告质量和服务目标尚无经过样本验证的量化基线。

评价目录中的指标和权重仅用于促进讨论。指标含义、量表、数据口径、缺失值与风险项处理方式尚需科技金融、行业、财务、风控和模型治理专家联合确认。

## 6. 主要未决问题

- 首期服务的机构、融资产品、行业和企业阶段。
- 首批资料类型、真实规模、质量分布、数据授权和保留要求。
- 部署边界、身份权限、网络隔离与模型数据出域政策。
- 尽调报告模板、专家复核方式、审批流程和最终验收标准。
- 指标量表、权重、风险否决机制与行业差异化方案。
- 技术栈、模型、解析器、存储、检索和工作流组件选型。

## 7. 下一阶段建议

### 7.1 完成业务与合规评审

组织尽调人员、技术/行业/财务专家、风控、合规和研发共同评审需求与术语，冻结一个边界明确的首期场景。优先确认输入资料、输出报告、人工责任和不能自动化的环节。

### 7.2 建立脱敏样本与金标准

选择少量具有代表性的企业案例，完成授权、脱敏和资料质量标注。由专家标记关键事实、证据位置、冲突、期望分析和不可判断项，为解析、检索和 Agent 评测提供依据。

### 7.3 进行有目标的技术验证

围绕最不确定的风险开展小型验证，例如复杂表格/扫描件解析、中文专业检索、引用正确性和权限隔离。比较成熟组件并记录成本、许可、数据策略与退出方案，避免先搭建大而全平台。

### 7.4 设计最小端到端闭环

限定一个企业、少量文档格式和一份报告模板，设计从资料导入到人工复核的完整验收路径。先定义接口和测试，再初始化前后端及基础设施。只有最小闭环稳定后再扩展多模态和更多 Agent。

### 7.5 建立变更与质量门禁

采用架构决策记录、代码评审、自动化检查、固定样本回归和发布风险评审。每次新增功能说明目的、影响范围、数据与安全变化以及验证证据。

## 8. 后续总结更新要求

每个里程碑结束后，本文件至少补充：计划与实际范围、交付物、可量化质量结果、重大决策、变更和原因、已关闭/未关闭风险、用户反馈、资源与成本、经验教训以及下一阶段进入条件。内容应以实际证据为准，不把计划描述为已完成事实。
