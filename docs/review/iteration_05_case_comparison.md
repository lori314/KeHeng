## Estun/hash 结构化失败

原始响应与格式修复响应均可解析为 JSON，SHA-256 前 16 位相同：`65ecaf22fcf5d76c`。两份响应均将 `summary_evidence_ids` 返回为 `[]`。离线按当前契约复验，首轮和修复轮唯一校验错误均为：

| 项目 | 结果 |
|---|---|
| JSON 语法 | 有效 |
| 字段类型 / 枚举 / 必填对象结构 | 未发现额外错误 |
| 失败路径 | `summary_evidence_ids` |
| Pydantic 类型 | `too_short` |
| 错误 | `List should have at least 1 item after validation, not 0` |
| 结果处理 | 技术模块失败；未保留成“证据不足”的指标结果，也没有可用的部分指标 |

提示词原有“无法判断时返回 null 和空 evidence_ids”可能让模型把指标拒答规则套到摘要引用字段；另一方面它也明确要求摘要绑定证据，因此输出仍违反有效契约。旧修复提示只要求“修正格式”，不传具体错误，是重试未修复的直接系统原因。本轮澄清摘要与指标引用规则；修复提示现在传递不含原始字段值的字段/类型/错误说明。未知 E 编号仍在 Agent task-context 校验时拒绝。历史 raw 未改写，修复效果仅由离线契约回归证明，未再次请求模型。
