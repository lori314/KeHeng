# KeHeng 真实企业案例人工复核说明

## 目的

本表用于对真实企业案例的模型抽取、证据引用和报告表达进行轻量人工复核。复核结果是质量控制记录，不是金融机构授信意见，也不构成对企业融资价值的事实认定。

## 复核范围

复核人应打开 `data/real_cases/<company_id>/manifest.json` 核对资料来源，再对照 `runtime/real_cases/<company_id>/` 中的分析、评价和报告 JSON。每一条关键结论都应能回到 E 编号、来源文档、页码和原文片段。缺少证据时应标记为“不合理”或在备注中说明“无法判断”，不得用行业常识补齐企业事实。

## 评价等级

- **合理**：结论与原文一致，证据足以支持，未扩大事实范围。
- **基本合理**：主结论可接受，但表述、证据覆盖或谨慎程度仍需微调。
- **不合理**：证据不足、引用错误、否定/未来语义被反转，或把行业趋势当成企业事实。

## 复核字段

使用 `data/real_cases/review_template.csv`，至少填写：

1. 技术分析合理性；
2. 产业分析合理性；
3. 证据支持程度；
4. 是否存在过度推断；
5. TRL 判断合理性；
6. 报告可读性；
7. 具体备注、涉及的 E 编号和页码。

复核时重点检查“计划量产”“正在研发”“尚未规模化”等未来或否定语义，确认系统没有将计划、研发中或未完成状态当作已实现能力。综合评分仍由确定性 Evaluation Engine 计算，复核人不应直接修改评分结果；如发现问题，应记录问题并回到指标证据层处理。
